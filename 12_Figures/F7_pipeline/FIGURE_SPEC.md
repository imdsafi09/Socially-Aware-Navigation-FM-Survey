# F7 Figure Specification: VLM-Enabled Social-Navigation Pipeline (conceptual, annotated with counts)

**Scientific question:** where in the navigation stack does foundation-model output enter, what consumes it, and which components does the FM augment rather than replace?
- **Type:** conceptual architecture with corpus counts.
- **Source:** Axis D counts and temporal-coupling attribute (QF09, QF13); T4.
- **RQ:** RQ3, RQ7.

## Layout: horizontal pipeline with a feedback loop

**Main flow (solid arrows):**
Sensors (RGB / RGB-D / LiDAR / language) → Perception and tracking (detection, tracking, SLAM / localisation, metric map) → **Foundation-model reasoning** (highlighted box) → Interface representation → Planner / controller → Safety layer → Robot execution → Humans and environment, which feed back to the sensors.

**Box contents:**

| Box | Content |
|---|---|
| Perception & tracking | "kept classical in most systems" (tracks, maps) |
| FM reasoning | Sub-labels for the roles R1–R5 |
| Planner / controller | "DWA / TEB / MPC / A* / SFM / RL policy" |
| Safety layer | "FM-independent guard: 18/41 overall; 11/18 systematic-robot papers; 0/5 direct-action" |

**Interface taps:** nine labelled arrows leave the FM box:

| Tap | Destination | Arrow style | Label |
|---|---|---|---|
| D1 | Planner input ("semantic / social state") | solid | n = 5 |
| D2 | Planner ("select candidate"), with a dashed back-arrow showing candidates proposed by the planner | solid | n = 5 |
| D3 | Planner objective ("costs / constraints / parameters") | **thicker** (most frequent) | n = 11 |
| D4 | Planner goal input ("goal / waypoints") | solid | n = 5 |
| D5 | Learned-policy box ("latent conditioning") | solid | n = 3 |
| D6 | Robot execution, **bypassing** planner and safety layer | red | n = 5 |
| D7 | Separate "training pipeline" box beside the stack | dashed | n = 8 |
| D8 | Human/environment box ("dialogue / explanation") | solid | n = 4 |
| D0 | Off-stack "offline evaluation" sink, outside the robot loop | grey | n = 8 |

**Clocks:**
- Slow clock (seconds) on the FM box; fast clock (ms) on the planner/controller.
- Bracket: "asynchronous slow/fast: 6/41; event-triggered: 1/41".
- Latency examples in small text: "VLM slow loop ~7 s vs SFM fast loop 5 ms (LISN)".

**"Augments, does not replace" band:** a light band under the perception and planner boxes listing metric mapping, localisation, dynamic feasibility and low-level control, with the label "provided by non-FM components in all runtime-coupled systems (28/41), except direct-action (D6) designs, which bypass the planner".

## Caption concept
"Where foundation models enter social navigation. FM output reaches motion through nine interface types. The most common, D3, shapes the objective of a classical planner that retains metric mapping, feasibility, low-level control and, often, an FM-independent safety layer. Direct action generation (D6) bypasses these components and is the least validated. Training-time use (D7) removes the FM from runtime. Counts: direct papers, non-exclusive (n = 41)."
